## Findings

### P1 — `tools/loopback_spike.py:87` — loopback endpoint resolved by name and never verified; produces a silent false PASS

```python
desktop_mic = sc.get_microphone(id=speaker.name, include_loopback=True)
```

`speaker.name` is a FriendlyName, not a WASAPI id, so `_match_device` (`soundcard/mediafoundation.py:163-183`) skips its exact `devices_by_id` lookup and falls through to substring then fuzzy matching. Nothing afterwards checks that the result is actually a loopback endpoint, or that it belongs to the default speaker. Two concrete inputs break it:

**(a) Prefix collision.** Default speaker `"Speakers"`, plus a second output `"Speakers (USB Audio)"` enumerated first. The substring test `if id in name` matches the *other* speaker:

```
Default speaker:    Speakers (id={0.0.0.x}.spk1)
Desktop loopback:   Speakers (USB Audio) (id={0.0.0.x}.spk2)   <-- wrong endpoint
========== VERDICT ==========
PASS: Simultaneous microphone and non-silent desktop capture succeeded.
```

It captures a device the user isn't playing through. When that device is idle the script prints `NO DESKTOP AUDIO ... This is a test-operator error, not evidence of a hardware failure` — actively blaming the operator for the tool's own mis-resolution.

**(b) Name shadowing.** `_match_device` builds `devices_by_name = {device.name: device for device in devices}` over `all_microphones(include_loopback=True)`, which returns **loopbacks first, real mics second** (`mediafoundation.py:145-149`). A capture endpoint sharing the default speaker's FriendlyName overwrites the loopback's dict key, so the lookup returns an ordinary microphone:

```
Default speaker:    Speakers (USB Audio) (id={0.0.0.x}.spk1)
Desktop loopback:   Speakers (USB Audio) (id={0.0.1.x}.mic1)   <-- isloopback=False
========== VERDICT ==========
PASS: Simultaneous microphone and non-silent desktop capture succeeded.
```

The script records the microphone twice, both streams are non-silent, and it reports PASS. The docstring claims a PASS "proves that SoundCard opened the default microphone and default speaker's WASAPI loopback together" — here it proves the opposite of what it printed. Because the verdict is this file's entire deliverable, a verdict that can silently lie is blocking.

The id is already in hand and `devices_by_id` has no speaker/mic collisions, so id lookup is deterministic. Verified both scenarios resolve correctly with:

```python
desktop_mic = sc.get_microphone(id=speaker.id, include_loopback=True)
if desktop_mic is None or not getattr(desktop_mic, "isloopback", False):
    raise RuntimeError("resolved endpoint is not a loopback capture device")
```

### P3 — `tools/loopback_spike.py:177` — `ZeroDivisionError` on a value that passes validation

`--seconds 0.00001` clears the `> 0` and `isfinite` guard at line 43, but `expected = round(0.00001 * 16000)` is `0`, and `drift = (frames - expected) / expected * 100` raises after the capture has already run — a traceback instead of the verdict block, and exit 1 indistinguishable from a real FAIL. Guard the division or floor `expected` at 1.

### P3 — `tools/loopback_spike.py:120,177` — the two health metrics can't detect the failure they exist for

`_Recorder.record(numframes)` (`mediafoundation.py:781-820`) zero-pads when the device supplies nothing and always returns exactly `numframes`. So `len(block) < requested` is never true and the frame total always matches the request total: a starved or dropping stream reports `short reads 0` and ~0% drift, and the padding shows up as silence rather than as a short read. Only the RMS check would catch it, and only for the desktop stream.

### P3 — `tools/loopback_spike.py:100,173` — output handling

`--outdir` writes `mic.wav`/`desktop.wav` into the given directory, overwriting existing files without prompting (the default timestamped path avoids this; an explicit `--outdir ~/Music` does not). Files land at 0644 — on the stated Windows target the profile directory's ACL covers it, so this is marginal, but the script does run on Linux via the pulseaudio backend, where mic and system-audio recordings would be world-readable.
